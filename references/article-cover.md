# 公众号文章封面

默认文章产物增加一张独立横版封面，严格2.35:1（47:20），推荐2350×1000或1410×600 PNG。封面不计入原图二创页数，不改变图组3:4比例；用户明确只要图片或省略文章时不强制制作文章封面。用户仅要文章与封面时记录局部交付，不能冒充完整图组流程通过。

先完成非空且不超过500字的独立文章，再从正文中心问题提炼恰好4个汉字。四字词必须准确概括正文，有明确主题，不用“干货满满”“必看攻略”等泛词，不用数字、英文、标点或空格凑4字，不把长文章标题直接裁成4字。四字词与文章标题是两种产物；两组各3个标题规则仍执行，封面四字不占正文长度。

四个字作为视觉核心，字体粗而清晰、对比鲜明、整词完整，不拆错、不漏字、无遮挡，不贴边；在缩略图尺寸查看仍可辨认。标题放在中央安全带内，给背景与插画留空间，避免被发布时的缩略图裁切影响；不能承诺所有微信展示入口裁切相同。默认仅呈现这4个主题汉字，不加额外副标题、年份、机构名、Logo、导流或虚构招聘信息。若封面确含招聘推荐内容，提示语仍按disclaimer.md判断，必要声明是四字主题之外的独立小字；只有通用主题词时不因文章讲了企业而自动加声明。

封面可延续同任务图组的配色、纸纹、插画语言，但重新设计宽幅构图，不能把一张3:4图强行裁成长图。使用宿主真实生图工具，保存提示词与最终文件；无生图能力时明确说明缺项，不用空白图片占位。要求工具按2.35:1生成；如仅有像素取整偏差，可以按明确要求的比例校准导出尺寸，保留完整画面，不裁标题或正文、不改变创作内容。偏差较大时重新设计/生图，不能把人物和字体拉伸变形后假称验收通过。

逐张实际打开封面，核对4个汉字、文章主题匹配、清晰可读、无机构导流、无截断遮挡及严格比例。文章正文、主题词或图片发生变化后重新检查，旧封面与复核不复用。脚本不执行生图，不自动理解正文或OCR，也不保证微信推荐。

## 报告与检查

文字目录默认article-cover/cover.png及article-cover/cover-report.json。报告包含passed、article_sha256（article_layout.body_hash的当前正文哈希）、keyword（4汉字）、file（相对报告目录）、sha256（真实图片哈希）、width、height、ratio="2.35:1"。只有宿主实际看图通过才设置passed=true。

text-review.json新增article_cover_report（文字目录内相对报告路径）、article_cover_report_sha256、article_cover_reviewed及cover_check。cover_check记录当前sha256、keyword、article_sha256、text_correct、layout_passed、theme_matched、issues、notes；全部实际核对后布尔才true，未解决问题不得清空。

```text
python scripts/article_cover.py --article "文字目录/article.txt" --report "文字目录/article-cover/cover-report.json" --review "文字目录/text-review.json"
```

完整交付check_delivery.py也执行同一检查，将封面与报告加入清单。缺封面、非2.35:1、非4汉字、文件越界、旧正文/旧图片/旧复核或未通过主题/文字检查均阻断。不要只更新JSON代替重做图片。
